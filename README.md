# Go Micro Lab

**Go Micro Lab** - это экспериментальный микросервис на Go, построенный по принципам чистой архитектуры. Проект создан для изучения и сравнения производительности различных технологий: gRPC, PostgreSQL, Redis, Kafka.

## 🏗️ Архитектура
Проект построен на **чистой архитектуре** (Clean Architecture) с четким разделением на слои:

```
┌─────────────────────────────────────────────────────────────┐
│                     API Layer (gRPC)                        │
│              ┌─────────────┐ ┌─────────────┐                │
│              │ CreateTask  │ │ GetTask     │                │
│              └─────────────┘ └─────────────┘                │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│                     Usecase Layer                           │
│ ┌─────────────────────────────────────────────────────┐     │
│ │         TaskUsecase (бизнес-логика)                 │     │
│ │     - CreateTask → сохраняет в БД + кэш + Kafka     │     │
│ │     - GetTask → сначала Redis, потом БД             │     │
│ └─────────────────────────────────────────────────────┘     │
└────────────────────────┬────────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────────┐
│                 Repository Layer (Ports)                    │
│     ┌────────────┐ ┌────────────┐ ┌────────────────────┐    │
│     │ PostgreSQL │ │ Redis      │ │ Kafka (Producer)   │    │
│     │ (хранилище)│ │ (кэш)      │ │ (асинхронность)    │    │
│     └────────────┘ └────────────┘ └────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
```

## 🛠️ Технологии

| Компонент | Технология | Назначение |
| :--- | :--- | :--- |
| **Язык** | Go 1.25+ | Основной язык разработки |
| **API** | gRPC + Protobuf | Высокопроизводительное RPC-взаимодействие |
| **Хранилище** | PostgreSQL 15 | Основное постоянное хранилище |
| **Кэш** | Redis 7 | Кэширование для снижения нагрузки на БД |
| **Очередь** | Apache Kafka | Асинхронная обработка задач (воркер) |
| **Тесты** | ghz | Нагрузочное тестирование |
| **Контейнеризация** | Docker + Docker Compose | Управление инфраструктурой |

## 🚀 Быстрый старт

### 1. Клонируйте репозиторий
```bash
git clone https://github.com/yourusername/go_micro_lab.git
cd go_micro_lab
```
### 2. Запустите инфраструктуру
```bash
docker compose up -d
```

### 3. Запустите сервер и воркера
```bash
# Терминал 1 - сервер
go run cmd/server/main.go
```

```bash
# Терминал 2 - воркер
go run cmd/worker/main.go
```

### 4. Проверьте работу
```bash
# Создайте задачу
grpcurl -plaintext -d '{"payload": "Hello, World!"}' localhost:50051 task.TaskService/CreateTask

# Получите задачу по ID
grpcurl -plaintext -d '{"id": "ваш-id-тут"}' localhost:50051 task.TaskService/GetTask
```

## 📊 Нагрузочные тесты
📦 Установка инструментов для тестирования

Для запуска нагрузочных тестов в этом проекте используется утилита ghz.
```bash
go install github.com/bojand/ghz/cmd/ghz@latest
```

### 1. Тест на запись (CreateTask) - проверяем запись в БД + Kafka
```bash
ghz --insecure \
  --proto internal/api/grpc/task.proto \
  --call task.TaskService/CreateTask \
  -d '{"payload": "benchmark with Kafka"}' \
  localhost:50051 \
  -n 10000 \
  -c 200
```
Создаём 10 000 задач с 200 параллельными соединениями.

Смотрим как быстро сервер создаёт задачу, сохраняет её в PostgreSQL, отправляет событие в Kafka и возвращает ответ клиенту.

### 2. Тест на чтение (GetTask) - проверяем кэш

Что делаем: Запрашиваем задачу по ID 10 000 раз с 200 параллельными соединениями.

Что проверяем: Как быстро сервер отдаёт данные из Redis-кэша (минуя базу данных).

Команда:
```bash
ghz --insecure \
  --proto internal/api/grpc/task.proto \
  --call task.TaskService/GetTask \
  -d '{"id":"e4bb4eec-4e21-4764-aacd-2cca7cc63cb4"}' \
  localhost:50051 \
  -n 10000 \
  -c 200
```
